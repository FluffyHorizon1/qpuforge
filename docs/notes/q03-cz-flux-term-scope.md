# CZ flux-noise term: intent and impact

Issue file: `q03-flux-term-e2q.md`. On `main` 78b9f8b. Local runs on 27 Nov 2026, not committed.

## What PR #2 did

`d7ab24d` ("count flux noise during the CZ") adds `cz_flux_err` to `e_2q` in `analyze()`
(`include/qpuforge/device.hpp`, the `p.err_2q = ... + p.cz_flux_err` line). This is the short-time 1/f infidelity of
the higher qubit at its CZ flux point. The term is not gated on `tc_model`, so it applies to **every design whose
higher qubit is tunable**, not just Alpha-1.

## Intent (as far as the PR says)

The commit message and the whitepaper describe it for Alpha-1: 2.0–4.6e-5 per CZ on a 23 ns gate. Neither mentions
other designs. Its size scales with the CZ duration squared (t² phase variance), so on long fixed-coupling CZs it is
no longer small. **Finnian needs to say whether the term is meant for all designs (then regenerate) or for Alpha-1
only.**

## Impact, measured

Mean `e_2q` from `analyze()` (designed pairs):

| Design | before PR #2 (`1cfa2b1`) | `main` | flux term per CZ on `main` |
|---|---:|---:|---:|
| `gen0_surface17()` (fixed g = 3 MHz, 187 ns CZ) | 4.09e-3 | **5.98e-3 (+46 %)** | 1.1–2.6e-3 |
| 3×3 grid, fixed g = 3 MHz | 3.87e-3 | 5.15e-3 (+33 %) | 0.7–2.0e-3 |
| 3×3 grid, fixed g = 4 MHz | 3.42e-3 | 4.19e-3 (+22 %) | 0.4–1.2e-3 |
| 3×3 grid, tunable coupler | 2.23e-3 | 2.26e-3 | 1.2–3.6e-5 |
| `alpha1()` | 2.40e-3 | 2.43e-3 | 2.0–4.6e-5 |
| `alpha1_v11()` / `beta1()` before calibration | 2.40e-3 / 2.15e-3 | 2.43e-3 / 2.18e-3 | as Alpha-1 |

What it does **not** move: the QEC and circuit emulators take `err_2q_ctrl` (control error) plus their own
decoherence model, not `PairReport::err_2q` (`emulator.hpp:66-75`, `qec.hpp:128,188`). So logical-error rates and
circuit fidelities are unchanged by this term:
- `examples/alpha1_review` built from `main`: Gen-0 eps 0.0120, exactly the pre-PR #2 rebuild value.
- `examples/design_study` built from `main`: every GHZ-9 / RCS-10 / QFT-6 fidelity is identical with and without the
  term (checked against the proposed fix below).
- Pulse-calibrated pairs (the v1.1 and Beta-1 reviews) overwrite `err_2q` with the calibrated value
  (`pulse.hpp:564`), so their CZ tables are unaffected.

What it **does** move (reported numbers only):
- `results/design_study.{csv,txt}`, the `mean_e2q` column: g = 2 MHz 4.75e-3 → 7.45e-3, g = 3 MHz 3.87e-3 → 5.15e-3,
  g = 4 MHz 3.42e-3 → 4.19e-3, Q sweep about +2.3e-5. (The committed fidelity columns already differ from a rebuild for
  reasons unrelated to PR #2; see the Monte Carlo provenance notes.)
- `mean_e2q` in review JSON (`alpha1_review.json` `alpha1.mean_e2q`; the v1.0 rows inside the v1.1 review), the
  `qpuforge analyze` table (`e_2q`, new `flux_e` column) and the fab Monte Carlo `err2q_mean`.
  `results/budget_*.txt` and `results/run_ghz5_*.txt` do not print `e_2q` and come from the emulators, so they are
  not affected.
- `results/test_output.txt` (already regenerated by PR #2).

## Other review points (not changed by the proposed fix)

- `flux_pulse_infidelity()`: the 0.4 prefactor in `0.4 (1 − exp(−x²))` has no derivation or reference, and only the
  higher (moving) qubit's flux error is counted.
- Fixed finite-difference step `h1 = 1e-4` and a silent skip when `flux <= 5 h1`.
- `test_coupler_and_flux` "exchange cancelled" checks compare `Jp(f_c)` at the root of the same `Jp` that
  `coupler_exchange_null()` bisects, so they pass by construction; a real check would compare against the
  three-level diagonalised |10⟩–|01⟩ splitting. The 300 MHz margin and `lo = 2.0` GHz bracket are hard-coded.
- The group takes 10–55 s because it calls `analyze(alpha1(3))` repeatedly.

## Proposed fix (branch `fix/cz-flux-term-opt-in`, code only)

- New `ChipDesign::cz_flux_noise` (default off; design JSON `gates.cz_flux_noise`). `cz_flux_err` is still computed and
  printed for every design, but it is added to `e_2q` only when the flag is on.
- `alpha1()` turns it on; `alpha1_v11()` turns it off (its pulse calibration has its own flux terms).
- Design JSON without the key follows `tunable_coupler.model_coupler`, so the PR #2 Alpha-1 files
  (`designs/alpha1/alpha1.json`, `examples/alpha1.json`) keep the term without editing them.
- Result: `gen0`, fixed-coupling and generic tunable designs get back their pre-PR #2 `e_2q` exactly (the
  `design_study` `mean_e2q` column then matches the committed file in every row). Alpha-1 keeps 2.43e-3.
- Tests: 3 new checks (opt-in arithmetic, preset flags, JSON default). 189 checks, 21/21 CTest on g++ 14.2 and
  clang 19.1.7, `-Werror`.

If the term is meant for all designs instead, keep `main` as is and regenerate `results/design_study.*`,
`results/budget_*.txt`, `results/run_ghz5_*.txt` and the review JSONs with provenance, and say so in the CHANGELOG.
